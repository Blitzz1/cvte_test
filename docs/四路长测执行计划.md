# 四路一小时稳定性执行计划

> 2026-10-28。用户已授权基础长测，预先记录边界与判据；结果另行填写，不提前宣称通过。

## 负载与收尾

- 默认四条完整1080p30、含音频链路：RTSP UDP、RTSP TCP及两条RTMP；使用本地已编码文件，不额外计入摄像头编码负载。
- 默认资源配置和阈值保持不变，故障注入关闭，不打开浏览器／原生额外预览，不启动八路。
- 一次采集60分钟，每10秒获取一次指标、应用及MediaMTX资源；保留原始观测、数据库与进程回执。时间统一保存UTC，用户提示转换北京时间。
- 检测进程另设62分钟硬截止，独立watchdog负责兜底；采集结束、异常或保护中止均按本轮PID、路径、创建时间清理应用及媒体服务。禁止杀无关进程。
- 应用私有内存超过512MiB或服务器超过256MiB立即停止；两者合计CPU按逻辑处理器归一超过20%连续两个采样区间则停止；连续3次采集失败停止。资源保护不等于温度监测，本轮无温度传感数据。

## 分析判据

1. 实际观测跨度达到3600秒，进程无崩溃、采集无缺失；若保护触发或采样异常，记录中止／失败，不以“存活”替代通过。
2. 启动前30秒单列。此后每路平均输出至少28fps，至少99%快照达到28fps，不能出现零输出；丢帧、冻结、重连事件逐一核对，不能只看平均数。
3. 启动后端到端延迟及音画偏差有效率各至少95%。有效数值与原始观测对应，高延迟不裁剪；漂移、空值和未知缺失分别报告。无注入时出现已证实丢失或异常重连须解释，不能按未丢失跳过。
4. 稳态内存从第5分钟起分析：比较初段及末段5分钟中位数、趋势斜率和峰值。末段相对初段超过64MiB或稳态线性斜率超过0.5MiB/分钟视为需调查，不仅凭低于保护上限判稳定。句柄和服务器内存同时检查。
5. 1小时资源曲线不能严格证明不存在任何内存泄漏；报告只作证据支持的稳定性结论。

帧率、有效率及增长门槛是本项目事先选定的工程验收规则，非行业强制标准。旧八路长测失败记录仍保留，本次四路不能自动代表八路合格。

## 命令

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run-stability.ps1 -Minutes 60 -IntervalSeconds 10
```

长测期间只做文档和证据整理，避免额外解码、构建或多视频浏览器负载。长测后核对进程清理，再分析原始数据及完成现场演练交付核对。
