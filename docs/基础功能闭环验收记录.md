## 1. 本轮缺陷及修正

### 漂移分段误把单帧抖动当作持续错位

普通Sintel素材的初轮漂移回归中，一帧真实输出间隔约93.55ms，音画偏差从−189.62ms短暂变化到−137.72ms。旧规则看到超过50ms变化立即清空拟合段，导致本来存在的渐进漂移一直无法积累足够连续时长。这不是时间减法错误，也不应删除该真实抖动。

新规则保留每个原始偏差：超过50ms的同方向偏移必须至少出现3个有效采样且持续至少100ms，才确认新段；确认期间漂移值为空，原因是step_confirmation_pending。单次抖动回归基线后取消候选。有效采样缺口超过0.5s、时间倒退及播放代次变化仍立即分段。连续跨度大于48秒、样本多于40个、拟合残差不超过15ms才发布漂移。以上为项目策略，非行业强制数值。

单测覆盖了渐变、单帧迟到、候选取消、持续阶跃确认及时间缺口。修正后四路普通素材回归中，音频每秒延后5ms，实测斜率约−4.96347ms/s，与目标−5ms/s相差0.03653ms/s；清除后恢复约24fps和十余毫秒的基线偏差。

### 服务断开仍可能留下正常卡片

旧页面只修改顶部连接提示，卡片可能保留上次的绿色状态及指标。现在断线后四张卡片均显示“服务未连接”，实时指标清空，运行数为0；诊断区注明是最后一次成功读取的记录。后台恢复后正常重连。未将旧数值继续当成当前正常状态。

### 验收脚本在预热前进入故障阶段

原脚本从启动时计时，普通B帧素材探测和等待关键帧期间可能耗尽基线／短故障阶段；一次75秒采集缺少有效音频延后样本，未计为通过。现最多等待25秒，确认每路已有实际输出及源端延迟参考后再开始阶段计时；整轮仍受显式硬截止约束，没有无限等待。结果增加warmup_seconds和all_stages_observed，但“采齐阶段”不等于“指标准确”。

## 2. 普通素材完整链路验证

源为未修改的Sintel官方预告片，H.264／AAC、1920×1080、24fps，含B帧，时长约52秒；无检测专用SEI、图像水印或声音标记。四路为RTSP UDP、RTSP TCP及两路RTMP，每路均实际推送、拉取、解码并输出。

修正后完整故障回归：`artifacts/short-20261028-085914-transitions/`，90秒上限，脚本约85.64秒完成，预热约16.82秒，45次快照，所有阶段采齐。应用私有内存峰值203.06MiB，CPU峰值约1.08%（按20个逻辑处理器归一）；原始证据丢失计数0、资源保护未触发。结束后检测程序和MediaMTX均退出。

RTMP第3路的代表性阶段值如下，所有有效结果均来自实际输出，重连预热期间不填造数值：

|---|---:|---:|---:|
| 基线 | 463.99 | −13.15 | 24.21 |
| 音频延后350ms | 461.86 | −362.49 | 24.12 |
| 音频恢复 | 454.72 | −10.16 | 24.34 |

- 音频延后相对基线变化−349.337ms，与注入目标−350ms差0.663ms。
- 视频延后相对前一稳定阶段增加801.557ms，与目标800ms差1.557ms；同步变化+801.173ms，与目标差1.173ms。
- 播放代次由4变为9；新会话预热期间指标为空，随后恢复，未复用旧代次的正常值。
- UDP实际丢包后，累计确认33个RTP缺口，成熟窗口曾确认33帧传输丢失；未知缺失最多127帧，说明受损预测链、未唯一关联输出等限制仍存在。不能把未知全算成已证实网络丢帧。恢复末尾RTMP第3路仍有1帧未知，已如实保留上下界。
- 清除视频延后时可能发生实际追赶丢弃，必须保留呈现丢弃事实，不宣称整个故障过程无损。

8阶段原始事实复算均通过：有有效值时，延迟均值和音画偏差中位数与报表差小于0.001ms。另对连续漂移阶段从原始设备位置、频率及PCM起点重建同步样本并线性拟合，斜率与API差远小于0.001ms/s。失效／无参考阶段按不适用记录，不算精度通过。

修正前失败记录保留于`short-20261027-201153-drift/`；修正后漂移通过记录在`short-20261027-235421-drift/`；预热不足的75秒采集在`short-20261028-001721-transitions/`。不同版本和失败结果不混作通过证据。

## 3. 测量误差与适用边界

| 项目 | 当前证据和界限 |
|---|---|
| 起点 | 文件帧按实时节奏进入推流链路的真实释放时刻；不包含文件制作时的摄像头采集／编码时间 |
| 视频终点 | Direct2D完成实际绘制、WIC像素可读取；包含软件输出工作，不包含屏幕发光、浏览器HLS额外缓冲 |
| 源收关联 | 原始VCL／AAC负载指纹、时间基准及旁路身份；B帧按画面关联，重复或损伤无法唯一确认时不得补造源时间 |
| 时间量化 | 内部以单调时钟微秒记录；微秒表示精度不等于微秒测量准确度 |
| 音频 | WASAPI设备消费位置映射到实际提交的PCM源媒体时间，检查代次、采样新鲜度和PCM段边界；不声称测到实际发声 |
| 15ms新鲜度门槛 | 是是否允许在有效PCM段内换算的条件，不是已经证明“绝对误差±15ms” |
| 受控差分实测 | 本轮普通素材代表阶段的固定偏移差值误差为0.663／1.557／1.173ms，漂移斜率差0.03653ms/s；仅适用于本轮素材、配置与观测边界，不外推为所有输入的统一绝对误差承诺 |
| 原始复算 | 验证事实到报表的一致性，共享观测点和时钟仍有共同误差；不等同于第二套独立物理校准或同步交叉验证加分项 |

基本公式、已知异常、普通素材和原始事实均有证据；没有把“数据能复算”与“物理端到端绝对校准”混为一谈。仅外部拉流缺少源参考、无音频、时钟失效等沿用既有明确的不可测／不适用处理，相关旧验证见测试计划与需求追踪表，本轮未重复增加这些媒体负载。

## 4. 内置浏览器功能验收

本轮实际使用已连接的内置Chromium浏览器访问`http://127.0.0.1:8080/`。原生Edge的自动操作此前因工具无法可靠识别当前URL被终止，因此本轮不宣称已完成原生Edge／Chrome兼容性演练。

| 功能 | 本轮实际结果 |
|---|---|
| 四路总览与诊断 | 四路卡片、1080p输入、音频采样率、实际输出及有效性可读 |
| 单路预览 | RTSP UDP与RTMP分别实际播放1920×1080，readyState=4，时间持续推进 |
| 关闭及切换 | 关闭后video.paused=true、src为空；切换RTMP后可再次播放，非只显示静态缩略图 |
| 固定历史范围 | 1／6／24小时均完成查询并显示“已更新” |
| 自定义历史范围 | 日期起止输入与查询完成；只查询真实已保存数据 |
| 单路停止／启动 | RTMP第3路停止时显示已停止及空指标，其他三路持续运行；启动后恢复 |
| 故障与告警 | 网页输入音频延后350ms后，该路约−363ms并严重告警；恢复后约十余毫秒 |
| 通知 | 当前测试时段记录6次本机webhook_received及6次成功webhook_delivery，可按event_id追踪 |
| 非法配置 | 警告延迟1500ms大于严重阈值1000ms，保存被拒绝，页面给出错误说明 |
| 合法配置 | 警告阈值450ms保存，revision变为4，阈值生效；仅修改本轮临时配置，不覆盖项目默认配置 |
| 页面重载／服务重启 | 450ms及revision=4仍保留；同一时间范围历史指标300条、事件27条在进程重启前后完全一致 |
| 服务断开／恢复 | 四卡片显示服务未连接，实时指标为空；新服务启动后页面重新显示已连接 |
| 页面脚本 | 本轮主动断线前后检查未发现捕获到的JavaScript错误 |

页面验收采用300秒硬上限，约232.57秒主动结束；应用私有内存峰值134.89MiB、CPU采样均值约1.14%、峰值约2.75%。随后重启回查采用60秒硬上限。两轮均自动清理应用及媒体服务；临时浏览器标签页已关闭，没有继续播放。没有为基础验收再次打开八路宫格。

## 5. 本地依赖及持久化检查

`scripts/check-runtime.ps1`已通过：运行程序、MediaMTX、素材、样式／脚本及本地hls.js齐备；7个FFmpeg运行DLL与本地准备目录哈希一致，hls.js与依赖锁哈希一致。浏览器实际加载的脚本与样式均来自本机8080；启动入口不调用联网准备脚本，媒体地址和本轮通知目标为本机地址。

这是本机依赖就绪和离线启动路径的证据，没有修改系统网络设置，也没有进行物理断网实测。仍应在现场演练时确认不依赖外部服务；可在不修改依赖的情况下复用现有启动入口。

新增storage_persistence测试：在独立临时数据库中写入指标与事件，关闭再打开确认保留；只调整测试记录时间至10天前，执行真实7天清理逻辑，确认旧记录删除、当前记录与事件身份保留，其他链路／空范围不造数据。没有更改系统时间或生产数据库，也不冒称已实际等待7天。

最终Release构建及三个CTest目标通过：detection_core、video_conversion、storage_persistence。所有媒体测试有截止、资源保护及自动收尾。
