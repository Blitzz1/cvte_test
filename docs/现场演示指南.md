## 1. 演示前准备

接电源，保留本机依赖缓存、构建产物与素材，避免运行其他高负载任务。优先使用 Edge 或 Chrome 打开本机8080看板；浏览器兼容性以实际演练为准。预先运行一次启动脚本和素材检查，运行时不下载依赖。不要临场刷新依赖锁文件。

默认配置 `config/app.json` 为2路RTSP＋2路RTMP，均独立推拉此前的1080p30含音频合成演示素材。ordinary-material.json保留Sintel普通1080p24／AAC；manual-start.json初始0路，随后网页逐路启动；no-audio.json第1路为真正视频单轨、其他路含音频。操作见[素材替换与逐路操作](./素材替换与逐路操作.md)。8路及HTTP-FLV示例仍使用普通素材，stability-four.json专供30fps负载验收。变更配置文件启动前先停止当前实例，避免端口冲突。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -Seconds 300
```

本机服务使用8080（看板）、8554（RTSP）、8555（UDP检测中继）、1935（RTMP）、8888（额外HLS预览）等端口；端口占用时先读日志。不要杀掉不属于本项目的进程。

上述入口为5分钟演示上限，到期自动结束检测程序和媒体服务器；现场可按实际讲解时长显式调整Seconds，结束仍应执行停止命令。演示前可运行scripts/check-runtime.ps1核对本地依赖。当前内置浏览器功能验收已通过，原生Edge／Chrome及物理断网现场演练仍需实际确认；不要把这两项写成已经通过，详见基础功能闭环验收记录。

## 2. 正常链路

此前普通素材UDP大关键帧突发丢包已通过4MiB服务器接收缓冲修正，并用原Sintel跨循环复验。历史未知上界不是确定丢包率，修复记录保留前后证据。默认延迟警告400ms仍可能被实际延迟触发，保留真实提示，不隐藏异常或临时调高阈值。

1. 总览确认所需链路均运行，默认素材显示1080p、30fps输入及48kHz音频，等待15～30秒让输出与丢帧成熟窗口稳定。若使用Sintel配置，应为24fps；视频单轨配置同步显示不适用。详情按钮可逐路启动、停止及重启，关闭额外预览不等于停止检测。
2. 点击任一路查看延迟、同步、丢帧图及观测有效性；诊断里展示实际输出帧率、关联覆盖率与分层结局。
3. 优先打开单路预览并切换，确认视频持续播放；宫格会增加额外负载，办公本不建议首次试用就开启。主预览复用实际WIC软件输出，最多10张／秒，不另拉服务器媒体；选择“原流对照”才启用独立HLS。监听按钮使用本机WASAPI实际输出，网页图像存在额外展示延迟。
4. 选择1／6／24小时或任意起止时间回查，查看异常事件；程序只展示已经采集的历史，不生成过去24小时的虚假样本。

## 3. 三类异常

原流HLS预览与主检测输出是独立路径。设置100%呈现丢帧后，主检测输出和主预览均停止更新，预览显示无新画面；只有显式打开的原流对照仍可继续播放；应查看实际输出帧率、呈现丢弃及成熟窗口。TCP／RTMP不支持UDP数据报注入，但支持页面中的接收后丢帧和呈现丢帧；二者均不等于网络丢包。诊断已改为逐项中文说明，详见[看板说明与故障注入口径](./看板说明与故障注入口径.md)。

每次只作用于选中的一路，观察其他路是否继续输出。清除后等待队列追赶及告警恢复；丢帧窗口含5秒成熟等待，不会瞬间清零。

| 操作 | 观察与解释 |
|---|---|
| 视频延后800ms | 延迟明显上升，音频相对超前，符号为正；持续超过阈值后出现告警 |
| 音频延后350ms | 音频相对滞后，符号为负；画面端到端延迟基本不变 |
| 呈现丢弃20% | 输出帧率下降，presentation_dropped增加；注入概率与跨阶段成熟窗口统计不要求逐点相等 |
| RTSP UDP丢包2% | 真实阻断UDP数据报，RTP包率及传输帧损失出现；传输损失与呈现丢弃分别显示 |

全部故障通过真实队列或数据报路径作用，检测器不直接读取预期结果。无唯一关联时，展示已证实丢失下界、可能丢失上界与限制，不宣称确定的网络归因。

## 4. 生命周期、配置和通知

停止并启动一路，等异步任务完成，其余路保持运行。修改阈值保存，演示非法阈值被拒绝；连接参数修改后重启相应路。日志、事件和配置保存到本机。

Webhook默认可设为 `http://127.0.0.1:8080/webhook-demo`。异常触发后，事件中按event_id核对alert、webhook_delivery与webhook_received；失败会有限重试并记录，不阻塞媒体线程。当前支持HTTP；进程重启不保证恢复内存中尚未发送的通知。

## 5. 结束与答辩

结束执行 `scripts/stop.ps1`（同样使用PowerShell调用前缀），只停止本项目登记且路径一致的进程。保留质量数据库、观测文件和测试证据。

讲解重点：源端释放与输出完成的时间差、原素材同步前提、音画正负方向、可靠传输与RTP序号差别、丢帧成熟窗口及分层证据、关联失败时的上下界、1小时稳定性实际结果与尚未完成的加分项。不要把可见预览、软件表面或依赖库自动统计混为同一测量。
