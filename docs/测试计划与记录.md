## 1. 验证规则

普通素材不插入检测标记，源端同步为前提；单元测试、实流、独立事实审计、浏览器、稳定性和物理校准分别记录。每次实验注明配置／素材、协议、版本或二进制哈希、时长、注入位置、预期与实际、有效性、资源、失败和清理。注入真值只事后核对，不生成检测答案。

“通过”仅限已测范围；历史报告中的多卡、HLS宫格、固定尺寸或早期归因是当时实现，不代表当前界面。新程序不能继承旧版一小时结论。当前未验收事项只维护在[需求追踪](./需求追踪与验收状态.md)。

## 3. 可复现入口

以下是验证入口，不表示本次已经重跑。完整构建后运行四项CTest；CMake／CTest路径见依赖文档或本机已安装工具路径。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1
ctest --test-dir build --output-on-failure
```

若ctest未加入PATH，使用VS附带CMake目录下的ctest.exe绝对路径；`scripts/build.ps1 -CoreOnly`仅构建／运行核心目标，不代替全部四项。当前四目标为detection_core、video_conversion、storage_persistence、output_preview。

前端入口为tests/diagnostics_tests.cjs、preview_tests.cjs、chain_pages_tests.cjs和close_pages_tests.cjs，使用已准备Node执行；Node和Python用于开发／审计，非主程序演示运行依赖。

| 验证工具 | 用途 |
|---|---|
| scripts/validate-short.ps1 | 指定1／4路及秒数的受控资源／故障短测 |
| scripts/validate-decoder-loss.ps1、audit-decoder-loss.py | 接收后与呈现前丢弃的对比及超时结局审计 |
| scripts/validate-preview.ps1、audit-preview.py | 真实JPEG身份、冻结、恢复、清理 |
| scripts/validate-chain-pages.ps1、audit-pipeline-timing.py | 新增隔离、真实六时刻及800ms延后 |
| scripts/validate-close-pages.ps1 | 关闭、历史保留、空配置与设备身份 |
| scripts/validate-receive-timing.ps1、audit-receive-timing.py | 三协议接收子段、UDP帧末与发送事实核对 |
| scripts/validate-interactive.ps1 | 最长300秒的受控人工操作窗口 |
| scripts/run-stability.ps1 -Minutes 60 | 固定stability-four的一小时保护采集；默认60分钟，非短测入口，需明确安排 |

对应脚本参数以源码为准，先停止既有实例；自动脚本使用临时配置、资源保护与finally清理，不覆盖日常配置。审计脚本接收该实验目录，不随意套用其他实验结构。
