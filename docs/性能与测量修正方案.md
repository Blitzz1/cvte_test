# 性能与测量修正方案

> 2026-10-27，依据八路长测失败结果。本阶段优先基础性能与测量正确性，不启动稳定性长测，不追加加分功能。

## 1. 已确认的风险

- 全分辨率BGRA排队100帧／路，八路理论容量约6.18GiB；接收线程在队列满时等待，可能把拥塞扩散到解码、音频和协议接收。
- 软件输出每次刷新重复复制、重画所有路图像；逐帧按ID线性扫描90秒源端账本。
- 运行期原始记录在媒体锁内同步写磁盘；音频设备重置也持有媒体锁，可能拖住其他消费者。
- 图像、音频块、设备位置及输出完成回调没有统一代次，重连时可能把旧读数送入新统计窗口。
- 同步外推没有明确的有效采样段终点；漂移拟合可能把一次性跳变／断续数据当作渐进漂移。
- 连接存活与软件输出健康没有充分区分。

## 2. 实施约束

输入仍为普通、未加标记的H.264／AAC，完整接入并解码1080p30。只对既定软件观察表面的图像作显示尺寸转换，浏览器额外预览保持原流分辨率；不能通过减少输入帧或修改检测结果制造性能改善。

视频像素缓存采用每路帧数、每路字节数、应用总字节数三重约束，并统计峰值与真实过载丢弃。满队列不阻塞协议接收；保留已排队的未来帧，拒绝新帧，避免不停替换未来帧导致永远无法到期输出。过时且已到期的帧可在明确边界丢弃，记录为呈现环节原因。

软件输出按小尺寸缓存转换，仅更新有新帧的位图／区域。字节预算覆盖排队、转换中及持有的显示像素；解码器内部内存单独说明，不把像素预算冒充整个进程内存上限。

原始事实改为有界异步写入，磁盘操作不持有媒体锁。日志积压或写入失败必须公开计数，不静默宣称原始证据完整。源端ID查询改为受保留策略约束的索引。

## 3. 测量正确性

1. 每次接收重连／源端重新建立播放代次；所有视频、音频和设备采样携带该代次。旧代次完成回调不更新新统计。
2. 重连清理音视频时间映射、样本窗口、队列及设备段；设备操作移出媒体锁。
3. 同步只使用同代次、有源端参考、足够新且仍处于有效PCM段内的设备采样。无效、静音填充、欠载及缺参考不得伪装成同步0。
4. 原始匹配的高延迟仍如实计算，不能按数值大小裁剪。播放追赶可以改变播放行为，但必须有真实丢弃或重新预热事实。
5. 同步采样缺口或固定偏差突变划分新的漂移拟合段；不足时长／拟合残差过大时不发布稳定漂移斜率。
6. 连接状态、输出健康、时间映射和持久化证据有效性分别公开。失去新图像输出时不能只显示running。
7. 传输损伤但仍成功呈现的帧，不算未呈现；呈现丢弃、解码失败、接收侧丢弃及未知缺失保持区别。

## 4. 验证安排

先编译与单元测试：预算并发／释放、慢消费者与未来帧、旧代次拒绝、音频段边界／读数新鲜度、漂移突变与缺口、损伤帧结局、异步证据溢出／落盘。

编译限制为2个并行任务。随后仅安排单路及四路的限时短测，核对实际资源、源帧关联、原始时间复算，以及固定延后、过载恢复和重连。每次有独立进程回执及到期清理，结束确认检测程序和媒体服务均退出。

本阶段不以短测替代一小时验收。四路一小时及八路扩展稳定性留待修正验证完成后再安排。具体数值与失败必须回填，不能用设计预算代替实测。

## 5. 实施结果

已完成上述性能与代次／时钟边界修正，构建及核心、像素转换测试通过；单路及四路限时回归完成并自动结束进程。实际资源与故障响应、原始延迟／同步复算、保留的失败和验收边界见[性能与测量修正验证记录](./性能与测量修正验证记录.md)。四路一小时与八路持续性能仍未验收，不在本轮追加。
## 6. 漂移分段后续修正

2026-10-28实测发现单帧呈现迟到会触发旧版50ms立即分段规则。现改为同方向至少3个有效样本、持续至少100ms后确认阶跃；候选期间不发布漂移，原始偏差不删改。普通素材漂移与固定偏差新回归及浏览器闭环结果见基础功能闭环验收记录，历史八路长测失败结论仍保留。
