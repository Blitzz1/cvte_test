# 性能与测量修正验证记录

> 2026-10-27。本轮对应基础性能和测量正确性修正，只做限时短回归，没有启动四路一小时或八路长测。

## 1. 已实施的修正

- 完整接收、解码原始1080p30；软件观测表面的像素缓存按默认320×180等比例转换。浏览器额外预览仍使用原始分辨率。实际Direct2D绘制、EndDraw及WIC像素可读后才记为呈现完成，不用计划输出时间代替实测。
- 视频队列同时受帧数、每路队列字节数和共享像素预算限制。满队列拒绝新帧并记录呈现丢弃，不阻塞协议接收。过期帧丢弃有独立计数。共享字节租约覆盖转换中、排队中及输出暂持的CPU像素；FFmpeg内部缓冲、D2D固定小位图、音频、日志等另计，64MiB不是整个进程的内存承诺。
- 原始事实写入改为8MiB有界异步队列，磁盘操作移出媒体锁；积压或写入失败公开证据丢失计数。源帧ID索引取代线性查找；解码器时间戳身份备用表使用弱引用并限制每流512项，避免被丢弃／不返回的访问单元长期保留。只复制、绘制有更新的格子；解码器默认每路一个线程，构建默认两个并行任务。
- 接收重建、源端重建及停止均推进播放代次，清理旧队列、映射与统计窗口。旧视频完成回调、旧音频设备读数不能进入新代次。WASAPI初始化、停止、重置移出媒体锁。
- 同步计算仅使用同代次、年龄小于15ms、仍在已提交有效PCM段内的音频设备采样。无映射、填充静音、设备读数过旧时显示无效，不填0。保留实际设备位置、频率、PCM起点及视频完成时间，可离线复算。
- 固定偏差突变超过50ms、有效采样间隙超过0.5s或时间倒退时切分漂移拟合段；连续有效跨度不足48s或残差过大不发布漂移斜率。这些是项目策略，不冒称行业强制标准。
- 连接状态、输出健康和证据完整性分开报告。损伤但仍成功呈现的帧不算缺帧；没有足够证据的缺失继续列为未知，包丢失不直接换算成帧丢失。

## 2. 自动化测试

Release构建成功，CTest两项通过：

1. detection_core：并发预算、共享租约最后释放、溢出保护、旧代次／过旧／超出PCM段的采样拒绝、漂移突变及缺口、有界日志溢出／落盘失败、损伤但已呈现帧的互斥结局，以及既有公式、RTP、冻结、告警测试。
2. video_conversion：从1920×1080原始帧转换320×180及非整齐尺寸319×179，检查目标缓冲末尾哨兵，拒绝错误步幅和不足缓冲。

本轮中间版本曾把原始宽度的步幅用于缩小后的目标缓冲，导致单路测试API失去响应；自动收尾已结束程序。该失败保留在本机artifacts中，没有计作通过。现已抽出有边界检查的VideoConverter，并增加上述针对性回归。

## 3. 实际短回归

全部使用本机普通H.264/AAC源、完整推拉及软件输出，不打开额外浏览器预览。每轮有独立进程回执、明确期限和自动清理；资源超限提前停止。结束后确认检测程序和MediaMTX均已退出。

| 项目 | 设置／时限 | 观察结果 |
|---|---|---|
| 单路常规 | RTSP TCP，30秒上限 | 软件输出约30fps，私有内存约46MiB；延迟原始时间复算一致 |
| 单路预算压力 | 每路队列仅1MiB、共享8MiB，30秒上限；视频延后800ms后清除 | 队列峰值921600字节，私有内存峰值约44.7MiB；真实记录429次预算丢弃。强限额下恢复后仍约10～11fps，不能称为正常性能通过；延迟和同步复算通过 |
| 最终单路接收丢弃 | 默认预算，20秒上限；完整视频访问单元100%丢弃后恢复 | 丢弃期间输出为0、同步为空；恢复29.71fps、同步−12.29ms，成熟窗口明确记录receiver_discarded；私有内存采样峰值45.56MiB，延迟／同步原始复算通过 |
| 四路故障及恢复 | 默认预算，75秒上限；采集脚本运行约71秒／54次快照 | 应用私有内存峰值127.74MiB；应用CPU采样均值1.35%、峰值3.27%（按20逻辑处理器归一，首个样本无差分为0）；共享像素峰值15.82MiB，未超过64MiB；资源保护未触发、原始证据丢失计数0 |

四路每路仍为1920×1080、30fps输入。恢复末尾四路输出分别约30.09、30.09、30.09、31.05fps（近1秒实际间隔估计有抖动）。这组数据是短时应用进程采样，不包含MediaMTX占用，不是散热或泄漏结论；与先前八路一小时结果负载、时长不同，不能作为同比性能比例。

### 故障响应与独立复算

RTMP第3路分阶段结果：

| 阶段 | 延迟ms | 音画偏差ms | 结论 |
|---|---:|---:|---|
| 基线 | 365.34 | −11.94 | 正常输出 |
| 音频延后350ms | 366.08 | −363.88 | 偏差相对基线变化−351.94ms，视频延迟基本不变 |
| 清除音频延后 | 367.08 | −12.51 | 恢复 |
| 视频延后800ms | 1167.90 | +787.12 | 相对前一阶段延迟增加800.82ms、偏差增加799.63ms |
| 清除视频延后 | 369.42 | −9.85 | 恢复约30fps；追赶过程21帧真实呈现丢弃，未伪造无损 |
| 重启后 | 359.57 | −12.19 | 播放代次4变为10，新会话重新预热；其他路持续工作 |

UDP路两秒100%阻断时出现输出停顿，延迟／同步为空；恢复后约30fps。累计实际RTP缺口629包，成熟窗口曾记录66帧传输丢失；还有最多9帧证据不足缺失，末尾窗口剩6帧未知。保持上下界，不把解码依赖或未关联输出强行算成已证实网络丢帧。

8个阶段快照的原始记录复算均通过：近1秒匹配帧的`mono_us-source_us`均值与API延迟差小于0.001ms；从设备位置／频率、有效PCM段起点和视频源媒体时间重算同步中位数，差小于0.001ms。失效阶段按不适用处理，无数值不算精度通过。复查最终会话原始事件，未发现任何software_present使用旧播放代次。

这项复算验证原始事实到指标的链路一致性，不等同于第二套独立的物理音画测量，也不宣称完成同步交叉验证加分项。
