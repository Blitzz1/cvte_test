# 当前版本与使用说明

> 更新：2026-10-29；程序基线63d6307，当前暂停功能改动。本文合并原素材操作与看板故障说明；实际设计及API以[设计文档](./设计文档.md)为准，完成范围以[需求追踪](./需求追踪与验收状态.md)为准。

## 1. 本机启动、配置选择与停止

在项目根目录PowerShell执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/check-runtime.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -Seconds 300
```

用Chrome或Edge打开 http://127.0.0.1:8080/，预留15～30秒预热；必须通过后台HTTP地址访问，不能直接打开index.html。依赖已提前缓存，启动不下载。不要并行启动多个配置抢占相同端口。

统一脚本默认 `config/single-chain.json`，首次模板为单路；新增／关闭页面会保存到该启动文件，下次按保存后的0～8条配置恢复。直接运行exe未指定配置时兼容app.json默认，不要混淆两种入口。显式选择配置：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -Config config/stability-four.json -Seconds 300
```

| 配置 | 用途 |
|---|---|
| single-chain.json | 统一入口默认，日常单页起步及保存后的页面集合 |
| stability-four.json | 固定四条1080p30含音频完整链路，用于标准负载验证 |
| manual-start.json | 预定义四个页面但不自动运行，可逐路启动；不是空注册表 |
| no-audio.json | 首路真正视频单轨且has_audio=false，其余含音频 |
| ordinary-material.json | 普通Sintel 1080p24含B帧素材 |
| app.json | 兼容配置，可显式选择；用户修改不自动还原 |
| eight-chains.json／http-flv.json | 加分实验配置，不代表稳定性或全部加分通过 |

网页读出的配置与本次启动路径一致，revision会随保存变化，不在说明中写死用户当前revision或路数。定时入口到期会清理本轮检测程序和媒体服务器；关闭网页不停止后台。省略Seconds是持续运行，提前结束用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/stop.ps1
```

办公本使用有限时长，自动验证须有资源保护及finally清理，完成后确认应用和MediaMTX都已退出；不要反复运行八路长测。

## 2. 页面、链路与三种关闭行为

每页只有当前链路的一张卡片、三张趋势图、诊断和两种预览。标签切换只更换观察对象，其他流持续推拉和检测，无宫格。

“新增页面”选择RTSP TCP／UDP或RTMP，填名称、素材路径、含音频声明，保存并启动独立本机链路。当前最多8条，自动分配不重复的流ID与本机地址；不重启既有流。外部独立拉流或HTTP-FLV仍通过JSON配置。

| 操作 | 效果 |
|---|---|
| 启动／重启 | 启动或重建本路推流、拉流、解码和软件输出；创建相应运行／播放批次 |
| 停止 | 托管路整条链路停止，页面及配置保留；其他路继续 |
| 页签×／关闭页面 | 先停止，再从运行注册表及配置持久移除；历史、日志、素材保留 |
| 关闭预览 | 结束该预览请求／播放器，不停止检测；音频监听使用独立控制 |
| 关闭网页 | 不结束后台 |

最后一页可关闭；空工作区可新增，空配置重启仍为空。关闭失败时页面保留供重试。独立direction=pull只管理本程序接收者，不能停止外部发布者。enabled决定应用启动时是否自动运行；运行中停止不会自动把enabled改成false。

## 3. 素材、音轨和替换

| 本机文件 | 视频 | 音频 |
|---|---|---|
| data/media/sample-3m.mp4 | 合成演示H.264，1920×1080、30fps | AAC，48kHz |
| data/media/sintel-trailer.mp4 | 普通H.264，1920×1080、24fps、含B帧 | AAC，48kHz |
| data/media/sample-1080p30-no-audio.mp4 | H.264，1920×1080、30fps | 没有音轨，不是静音音轨 |

各路可以使用同一文件或不同文件，流地址、运行身份与统计独立。正式测量不要求素材带标记；源素材自身同步为前提。视频单轨由复制视频压缩流并移除音轨生成，未覆盖原文件；哈希及来源见[第三方说明](./第三方组件与素材.md)。

替换已有链路：将文件放入data/media，进入“运行配置”JSON编辑器修改该链路source和has_audio，保存后重启该路。路径支持项目相对路径或绝对路径，JSON建议用正斜杠。没有网页文件上传功能；已有链路的has_audio需在JSON对象中补写，新增页面对话框另有含音频勾选项。

```json
"source": "data/media/my-video.mp4",
"has_audio": true
```

真正无音轨使用false，同步为空且不适用；视频延迟、丢帧和冻结继续检测。H.264／AAC是已验证主格式，不能因扩展名为mp4便保证其他编码兼容。需要生成另一份无音轨文件时可使用scripts/prepare-no-audio.ps1，脚本不覆盖现存输出。

网页保存自动校验并持久化本次启动配置；保留读出的revision，409冲突先重新加载。阈值等设置立即生效，素材／连接参数保存后需重启对应路。直接在磁盘编辑JSON不会自动热读，应重启应用；运行中新增／关闭应优先用页面入口。

publish_url与pull_url是逐路字段；缺pull_url取同一路publish_url，不是复用第一路地址。RTSP UDP检测路径使用8555中继，与发布地址8554不同，需保留显式pull_url。服务端口与资源字段见设计。

## 4. 检测预览、原流对照与监听

“打开检测画面”复用本路WIC完成后的实际内容像素，按需最多10次／秒编码JPEG并替换网页图片，不增加服务器媒体拉流或解码。实际画面按比例占满预览宽度，排除内部布局留黑；16:9单路约1000×563，四路每路约500×281。软件检测仍按源帧输出，10Hz镜像不是检测帧率；素材自带黑边不裁掉。

无新输出保留最后真实画面并提示新鲜度，停止／重连清理旧画面。100%呈现丢弃会冻结该检测镜像。“原流对照”显式打开后才另拉MediaMTX按需HLS，默认静音；检测端的接收／呈现丢弃不作用于对照流，故对照仍可能流畅。不打开对照时，网页不会为它主动持续拉HLS。

音频监听使用本机WASAPI实际输出，JPEG另有浏览器显示延迟，不能用肉眼听觉对比替代同步指标，也不能宣称浏览器内同步30fps音视频播放已完成。无预览时主WIC／音频观测仍运行。

## 5. 卡片与观测口径

| 显示 | 含义 |
|---|---|
| 卡片传输延迟／首图 | 源端实时释放→av_read_frame返回完整压缩帧立即打点；含发送、服务器、接收解封装和组帧等待，不是纯网络时间 |
| 完整端到端 | 同源帧释放→WIC实际完成；现有延迟告警仍按此值 |
| 接收后分段 | 哈希、锁等待、源帧查找与记录、其他记账；再列提交前处理、解码及解码后呈现；均为真实打点 |
| 音画偏差／漂移 | 视频呈现时的音频源媒体进度减视频进度；正值音频超前，负值滞后；漂移表示偏差随时间变化 |
| 视频丢帧率／结局 | 成熟源帧集合的最终呈现结果；未知列范围，不把没有找到身份一律称确定丢帧 |
| 冻结 | 距上次WIC新帧输出的间隔超阈值；静态内容持续有新帧不算冻结 |
| RTP丢包 | 仅当前UDP中继路径上的序号缺失，非整条链路抓包；TCP底层丢包／重传未实现 |

源端内部ID在释放媒体单元时建立，并经旁路匹配传给解码与呈现；音视频共享ID序列，不能用相邻视频ID相减算丢帧。当前30fps素材RTSP约多一帧组帧等待有实测支持，非协议强制；不人为扣除一帧，详见[计时核对](./预览与接收计时核对记录.md)。

近1秒传输与完整呈现分段使用不同有效样本集合，公开样本数；只能用归因区同组分段核对加法，不能把独立均值硬相减。null、不可测、不适用和证据不足均不是0或正常。

## 6. 故障注入与归因

| 选项 | 真实作用位置／适用范围 | 解释 |
|---|---|---|
| UDP丢包 | 8555中继路径扣留视频RTP数据报；仅RTSP UDP | 包缺口与帧损伤分开记录，不将包数等同帧数 |
| 接收后丢帧 | 完整压缩单元取得后、送解码前；RTSP／RTMP及已实现HTTP-FLV | 记receiver_discarded，可能影响后续依赖帧解码 |
| 呈现丢帧 | 已解码后、WIC输出前 | 记presentation_dropped，解码参考仍保留 |
| 视频延后 | 视频输出队列实际等待 | 主要抬高解码后呈现和完整端到端，不应抬高卡片传输值 |
| 音频延后／渐变 | PCM播放队列实际延后 | 音频滞后，偏差向负方向变化；渐变用于验证漂移 |

百分比是对每个候选单元的随机概率，不是最终每100帧固定损失数量。接收丢弃可能放大解码影响，短窗口有抽样波动；切换故障后旧样本仍需滑出。默认丢帧集合为源年龄5～15秒的10秒成熟窗口，pending不算确定结局。

成功提交后再独立等待默认5秒，仍无对应画面才按证据分解码未产出、输入缺失关联或UDP损伤后未产出；EAGAIN正常等待、已解码排队不直接算解码失败。具体参考依赖未解析，不强断根因；歧义输出等仍保留未知上下界。注入真值独立落盘，不拿设定概率当检测答案。

## 7. 历史、通知与数据保留

近5分钟实时曲线随当前页面积累；历史支持近1／6／24小时及任意起止范围，只显示已采集数据，不补造过去样本。按已关闭链路ID查询历史API仍有效；网页页面移除后不会继续显示该链路实时详情。

指标／事件写data/quality.db，关闭或重启后仍可查。原始逐帧事实写data/observations，注入真值另存*-truth.jsonl，日志写data/logs；默认保留7天并周期清理，活动文件轮转后按策略清理。运行文件和素材不纳入Git，默认不保留完整受损接收录像。

HTTP Webhook可指向http://127.0.0.1:8080/webhook-demo，发生／升级／恢复事件可按event_id追踪发送与接收，最多3次尝试。通知在独立线程，HTTPS与持久出站队列未实现；进程退出不保证恢复未发送通知。API和指标字段完整定义见设计，剩余验收见需求追踪。
