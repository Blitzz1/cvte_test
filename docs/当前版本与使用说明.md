# 当前版本与使用说明

> 更新：2026-10-28，北京时间。本文汇总当前默认配置、使用方法、交付状态及证据边界。各报告中带日期的实验保留当时条件；历史计划不代表尚未实施，也不代表实验已经通过。

## 1. 当前默认素材和配置

- `config/app.json` revision 5：四条独立完整链路，RTSP UDP、RTSP TCP及两条RTMP。每条链路独立推流到MediaMTX、拉流、解码、软件输出和检测；共用文件不等于共用一条流。
- 默认源文件恢复为 `data/media/sample-3m.mp4`：此前的合成演示视频，H.264／AAC、1920×1080、30fps、48kHz音频。普通Sintel 1080p24素材保留供回归；新增sample-1080p30-no-audio.mp4视频单轨文件。均不植入检测标记，循环时连续推进传输时间戳。各素材、替换与逐路控制见[操作指南](./素材替换与逐路操作.md)。
- `config/ordinary-material.json` 使用Sintel普通24fps素材；八路、HTTP-FLV及独立拉流示例仍保留普通素材。manual-start.json可初始0路再逐路启动；no-audio.json为第1路视频单轨、其他路含音频。独立拉流配置中的source字段不表示会自动推流，仍需有实际上游。
- 演示无需更换素材。每条链路可另配同步H.264／AAC文件；在网页保存素材路径后需重启相应链路。素材自身同步是前提，程序检测链路引入的偏差，不做口型语义识别。
- `config/stability-four.json` 独立保留1080p30合成素材负载；`run-stability.ps1` 明确读取它，防止将普通24fps文件套入至少28fps的长测判据。该配置不改变日常默认素材。

## 2. 启动和结束

在项目根目录PowerShell执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/check-runtime.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -Seconds 300
```

浏览器访问 `http://127.0.0.1:8080/`，等待15～30秒。先看四张卡片，再选单路预览、诊断和历史；默认合成素材输入30fps，显式Sintel普通素材输入24fps。办公本优先单路额外预览，避免同时启动多个应用实例。依赖和素材已在本地缓存，正常启动不下载。

该入口运行5分钟自动退出并清理本轮检测程序和媒体服务。省略Seconds会持续运行，关闭网页不会结束后台。提前结束：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/stop.ps1
```

自动测试必须有时限、资源保护和清理核对；不因文档更新重复长测。复现1080p30一小时负载仅在安排好时运行 `scripts/run-stability.ps1 -Minutes 60 -IntervalSeconds 10`，沿用独立合成配置与既有工程判据。

## 3. 数据保留

| 内容 | 位置及语义 |
|---|---|
| 历史指标、异常事件 | `data/quality.db`，SQLite持久化，停止、重启程序或电脑后仍可查询，默认保留7天并周期清理 |
| 实时5分钟曲线 | 当前页面实时积累；重新打开页面后，通过历史范围查询之前的数据 |
| 原始旁路观测 | `data/observations/*.jsonl`，分段保存；注入真值单独记录，不直接提供检测答案 |
| 日志及运行产物 | `data/logs/`、`artifacts/`、`runtime/`；有轮转日志、启动输出及进程回执，部分启动输出下次运行可能覆盖 |
| 已保存配置 | 启动时使用的JSON文件；阈值即时生效，素材及连接变更需重启链路 |

停止程序不会清空历史，后台停止期间不产生新样本。默认不自动录制完整接收视频；原始观测不等于录像或完整离线媒体复盘。运行产物及本地素材不提交Git，交付时须保留本地依赖和素材。

## 5. 普通素材切换的历史验证及后续修复

已核对普通文件SHA-256与已有素材记录一致，ffprobe确认H.264、AAC、1920×1080、24fps、48kHz及52.208333秒。四路限时90秒基线检查使用默认配置副本、资源保护及自动收尾；采样在约85.61秒完成，预热约12.29秒、共72条快照，覆盖一次文件循环。资源保护未触发，应用私有内存峰值约213.19MiB，收尾实查无检测程序或媒体服务器残留。本轮未开浏览器额外预览，也未重复一小时负载。

| 链路 | 末次输出fps | 延迟ms | 音画偏差ms | 末次成熟窗口结局 |
|---|---:|---:|---:|---|
| RTSP UDP | 24.193 | 477.117 | −13.434 | 240帧中127已呈现、2呈现丢弃、111未知；已证实下界0.833%，可能损失上界47.083% |
| RTSP TCP | 23.969 | 473.115 | −10.915 | 该窗口已证实／未知缺失均0 |
| RTMP第3路 | 23.937 | 454.442 | −13.212 | 该窗口已证实／未知缺失均0 |
| RTMP第4路 | 23.937 | 454.462 | −13.214 | 该窗口已证实／未知缺失均0 |

**修复前历史问题：普通B帧素材的UDP成熟窗口存在较高未知缺失。** 末次UDP中继累计RTP序号缺口为0，不能把47.083%的上界解释成真实网络丢包率，也不能因约24fps输出就认定归因正确。该次试验未给出根因结论；后续解码边界记录与服务器日志确认大关键帧处存在上游UDP接收突发损失，显式增大MediaMTX接收缓冲后跨循环复验已消除该固定位置问题，详见UDP修复记录。历史快照不改写为修复后数据。延迟超过默认400ms警告门槛时也会如实告警，不为演示改阈值。

精简原始证据：[运行摘要](./evidence/2026-10-28/default-ordinary/summary.json)、[末次链路快照](./evidence/2026-10-28/default-ordinary/last-chains.json)、[脚本结果](./evidence/2026-10-28/default-ordinary/result.json)、[本地依赖检查](./evidence/2026-10-28/default-ordinary/runtime-check.json)。完整快照留在本机 `artifacts/short-20261028-113912-baseline/`。这些是运行与素材切换证据，不是完整精度／稳定性通过结论。
