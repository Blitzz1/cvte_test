## 4. 可确定的问题与待验证原因

**代码中可直接确认的资源风险：**当前每个1920×1080 BGRA图像约7.91MiB，队列上限100帧；八路仅排队图像的理论容量约6.18GiB，尚未计入解码器、输出图像及渲染位图。这种队列设计不适合当前办公本。实际快照也记录了队列接近或达到上限。

另一个待优化点是共享软件渲染循环：每次更新会遍历各路图像，重复执行全分辨率位图复制与绘制。八路同时停顿、同时降帧，提示应优先剖析共享输出及锁等待；目前没有线程栈或耗时分段证据，不能宣称已精确定位唯一瓶颈。

下一阶段优先顺序：

1. 收紧**总字节预算**和每路队列，采用明确的过载丢弃策略并保留归因，避免长期背压后集中积压。
2. 减少全分辨率BGRA常驻和重复转换／复制；评估保留紧凑解码帧、按实际输出尺寸转换、仅更新发生变化的位图。
3. 区分连接存活、输出健康、观测失效；复核欠载／重连后的同步映射，防止误导性正常状态。
4. 补充低开销的渲染耗时、队列字节数和锁等待观测，再确定具体瓶颈。
5. 优先单路和四路有明确时限的短测，优化后再安排基础四路一小时验证；八路长测后置，不立即在办公本上重跑。

本轮八路未通过，不等于已经证明基础四路也未通过；基础四路仍需单独完成稳定性验收。
